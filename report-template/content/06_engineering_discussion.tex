\section{Engineering Discussion}

\begin{example}{Numerical Reliability}{ex:reliability}
A visually reasonable simulation result is not automatically trustworthy. Mesh density,
boundary placement, solver convergence, sampling, and parameter sensitivity should be checked
whenever the reported behavior is anomalous or non-monotonic.
\end{example}

\begin{problem}{Limitation Statement}{prob:limitation}
The example data in this template are synthetic and have not been validated against physical
measurements. They must not be presented as experimental evidence.
\end{problem}

The template deliberately separates claims from supporting evidence. Tables should report the
quantities that matter to acceptance; figures should make trends and anomalies visible; source
code should be included when it materially improves reproducibility. For electromagnetic and
array-processing projects, analytical expectations should be compared with numerical results,
and discrepancies should be discussed rather than hidden.

\interp{A professional report demonstrates engineering judgment by explaining why a result is
credible, what limitations remain, and what additional test would reduce uncertainty.}
